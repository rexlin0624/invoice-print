## 1. PDF 生成：双管道

参考实现的主线是「**矢量优先，失败才栅格化**」：

```
首选  直通管道  ：源 PDF 页面 → Form XObject（矢量保真）→ 按槽位算矩阵 + 裁剪 + Do
                 图片/OFD  → 编码成 JPEG DCTDecode 的 Image XObject
回退  渲染管道  ：光栅化后重新拼 PDF
```

两条硬知识：

- **标注（印章/签章）不在页面内容流里，在 `/Annots` 的 `/AP /N`（外观流）里。**
  要印章显示出来，必须把 `/AP /N` 的内容流烘焙进页面的内容流，并跳过隐藏标注；
  且**必须在标注绘制命令之前补一个 `Q`**，否则图形状态栈不平衡会把整页搞乱。
- **源 PDF 的 `/Rotate` 属性要烘焙进内容流前缀**（PDF 规范：显示时**顺时针**旋转）。
  90° = `[0 -1 1 0 0 w]`、180° = `[-1 0 0 -1 w h]`、270° = `[0 1 -1 0 h 0]`。

本仓库（网页版）走的是 pdf-lib 的 `embedPage` + `drawPage`，等价于「直通管道」——
pdf-lib 自己会带上页面资源。已实测：两张真票原样嵌入产物 206 KB，
与源文件之和 213 KB 同量级，说明字体/资源确实被复制过来了，不是转图。

## 1.5 渲染层：一份实现，两个宿主（2026-10 起）

「把一页变成像素」的需求有五处：预览缩略图、二维码扫描、白边探测、黑白/栅格化、OCR 前栅格化。
它们以前各自 `getDocument` + `page.render()`，现在全部走同一条路：

```
lib/render/client.ts   选宿主、拷贝字节、空闲回收   ← 应用代码只认它（renderPage()）
      ├── lib/render.worker.ts（默认）  ← 串行排队；pdfjs 用**微任务**推进，与标签页可见性无关
      └── lib/render/engine.ts（兜底）  ← 老浏览器没有 OffscreenCanvas 时原地跑
lib/render/engine.ts   唯一的渲染实现：pdfjs 装载参数 + 画布 + 阈值化 + 白边扫描 + 编码
lib/render/types.ts    请求/结果契约（按意图给选项：dpi / scale / maxWidthPx / box / boxFrac）
```

三条硬纪律：

1. **`engine.ts` 不许碰 `document`**（它要跑在 Worker 里）。画布与字体是唯一的环境差异，
   各自做了探测：画布优先 `OffscreenCanvas`；字体有 `FontFaceSet` 就走 `FontFace`，
   没有（老引擎的 Worker）就 `disableFontFace: true` 让 pdfjs 直接画字形轮廓 ——
   **必须显式关**，否则 pdfjs 会退到「往 DOM 插 `@font-face` 规则」，Worker 里当场崩。
2. **必须有自定义 `CanvasFactory`**。pdfjs 默认的 `DOMCanvasFactory` 调
   `document.createElement('canvas')`；主画布是我们传的，**辅助**画布（蒙版、图案填充）走它，Worker 里一遇就抛。
3. **同一时刻只画一张**：Worker 里请求排队串行。这台 8 GB 的机器上并发两张 A4@200dpi 就是危险区。

调试点：`globalThis.__invoiceRenderEngine = 'worker' | 'main'` 可以强制某条路
（`pnpm e2e` 就是靠它对比两条路的结果）。

## 2. `[M2]` 老打印机兼容（图片 PDF）

有些老打印机会栽在：透明度组（SMask）、嵌入字体、对象流 / 交叉引用流上。
参考实现的做法（默认关）：生成完成后把整份 PDF **逐页栅格化**再重建：

```
PDFium 白底渲染 300 dpi（含标注/签章）→ PNG → JPEG
→ 重建 PDF 1.4 + **经典 xref 表** + 每页一个 Image XObject（纯位图 PDF）
```

要点是**经典 xref 表**（不用交叉引用流）和**白底**（不留 alpha）。

## 3. 裁掉白边（已实现）

参考实现踩到的坑：白边裁剪的坐标是**基于预览缩略图**（`THUMB_MAX_DIM=600`）算出来的，
而实际执行裁剪时读的是**原图全分辨率**。
进裁剪器之前必须按 `ow/tw`、`oh/th` 换算到原图坐标，否则打印结果与预览整体偏移。

本仓库的做法（与参考实现的差别都在「保真」和「别裁错」上）：

- **矢量裁剪**：用 pdf-lib 给原票面页加一个**裁剪路径**（clip），**不栅格化** ——
  矢量的照旧矢量，不降清晰度。只有走「黑白 / 老打印机兼容 / 图片票」时才栅格化（见 §2）。
- **探测**：`detectContentBox()` 按 72 dpi 渲染整页 → 找内容边界（墨迹阈值 `INK_LEVEL = 245`、
  四边各留 4 px）。覆盖率 > 0.97（整页都是内容）或 < 0.2 时**拒绝裁**：宁可留白边，不可裁掉内容。
- **只裁单页票**：多页票各页边界可能不同，套同一个框会裁掉某一页的内容（见 `lib/detect.ts` 文件头）。
- **裁了就关旋转**：`anyCropped()` 为真时强制 `allowRotation = false` —— 裁剪 + 旋转是两层坐标变换，不值得为省纸冒险。

### 3.1 `crop` 是三态，不是布尔

`IntakeItem.crop: Box | null | undefined`：

| 值          | 含义                                                         |
| ----------- | ------------------------------------------------------------ |
| `undefined` | **还没探测过** —— UI 据此决定要不要跑探测                    |
| `null`      | **探测过、不裁**（本来就没白边 / 覆盖率异常拒绝 / 超时失败） |
| `Box`       | 裁到这个框                                                   |

早先只有 `undefined` 一种「不裁」，于是「探测过但不裁」被当成「没探测」：
探测 effect 的依赖每轮都判定「还有票没探测」，**无限重跑探测**，
进度条永远停在「正在识别白边…」（后台标签页里渲染会超时，必然触发）。
这个三态必须保留。

另外两条 UI 诚实性约定：

- 工具栏的「已裁白边」只能由 `anyCropped(printItems)` 决定，**不能只看开关** ——
  开关打开只代表「想裁」。
- 探测 effect 的依赖要用**稳定 key**（票 id 拼成的字符串），不能直接把数组放进 deps：
  `state.items` 每次「标记 / 跳过 / 库同步」都会换引用，会让 effect 被无谓取消重跑。

### 3.2 超时看门狗

探测要渲染整页，而后台标签页里 pdfjs 的 `render()` 依赖 `requestAnimationFrame`，
会被浏览器暂停 → 永远不 resolve（`解析规则参考.md` §7.10 有源码级解释）。
2026-10 起**渲染整体搬进了 Worker**（`apps/web/src/lib/render.worker.ts`），
Worker 里 pdfjs 改用微任务推进，这条路已经不再受标签页可见性影响。

看门狗仍然留着：坏文件、超大页、以及老浏览器（没有 `OffscreenCanvas`）
退回主线程那条路都需要它。白边探测 15s、二维码 15s、OCR 120s。

> 顺带一提：以前「后台标签页里预览一直显示『渲染中…』、切回前台就自己好了」
> 不是卡死，是 rAF 被暂停。搬进 Worker 之后这个现象应该消失了。

> 区域渲染（缩略图 / 二维码 / 栅格化共用的那套 `transform`）还有一个更隐蔽的坑，见 §7。

## 4. 网页打印的实现（本仓库现状）

字符版：

```html
<!-- 一个隐藏容器，打印时把排版好的 HTML 塞进去 -->
<style>
  @page {
    size: 210mm 297mm;
    margin: 0;
  }
</style>
<div id="printRoot" class="printing"></div>
```

```js
root.innerHTML = sheetsHtml();
window.print();
```

三个坑：

- **`margin: 0` 必须显式写**，浏览器默认会给页边距，于是「A4 排版」实际印出来不是 A4。
- **打印份数是「整版打几份」，不是「每张票重复几次」。** 参考实现用
  `printCopies` 重复整份 sheet，而不是展开单张票 —— 概念不同，UI 上要分开。
- **`window.print()` 在 WKWebView / WebKit 里是异步面板：调用后立刻清空 DOM 会出现空白页。**
  参考实现干脆不清（`doPrint()` 里注释写明）；本仓库走的是「生成 PDF 后用隐藏 iframe 打印」，
  天然避开这个问题，但 iframe 清理要延迟（`printBytes` 里等 60 秒再 revoke）。

## 5. 汇总表（本仓库现状：表格导出 + 打印前汇总条）

参考实现的汇总表列口径（9 列，每页 26 行）：

```
#, 票种, 发票号码, 开票日期, 购买方, 销售方, 不含税, 税额, 价税合计
```

本仓库现在有三条「汇总」出口，各自解决不同场合：

| 出口 | 位置 | 给谁用 |
| --- | --- | --- |
| `summarizeBatch()` + 汇总条 | 合并打印页顶部 | 打印前扫一眼：张数、金额合计、已识别率、缺金额/缺号码张数 |
| `summaryText()` + 「复制统计」 | 同上 | 贴进微信/邮件对账（纯文本，不涉及公式注入） |
| `buildExportTable()` → CSV / XLSX | 转 Excel 页、已报销库 | 要给财务的表；金额是**数字**能合计、号码/税号是**文本**不会变成科学计数法 |

三条都走内核的**同一份口径**（`invoiceTotal()`：优先价税合计，其次不含税 + 税额；
拿不到就是 `undefined`，**绝不当 0 元**）。缺金额的票单独计数 ——
「漏了一张」和「这张 0 元」在账上是两件事。

两个值得抄但还没抄的设计：

- **汇总表跟着发票一起打出来**（参考实现的 `S.printSummary`：先出 N 页发票排版，
  再附上汇总表页）。报销时「票 + 清单」是一起交的，多这一步能省掉一次单独打印。
  没做的原因：pdf-lib 内置字体只认 ASCII（见下），要打中文表格得先解决 CJK 字体
  —— 要么内嵌字体文件（几 MB + 授权），要么整页栅格化（丢矢量）。归到 M3+ 的报销单版式一起做。
- 三个金额列**合计行 sticky**，滚动时一直可见（我们是表格导出，没有滚动这一说）。

⚠️ **纸面文字只能是 ASCII**：`print.ts` 的页码、`lib/calib.ts` 的校准页都靠
`StandardFonts.Helvetica`（WinAnsi）。写一个汉字会直接抛
`WinAnsi cannot encode ...`，而且这类按钮通常不在主流程上，没人点就发现不了 ——
所以校准页有单测（`lib/calib.test.ts`）专门把「生成一页 A4」跑一遍。

## 7. 踩坑：区域渲染时 pdfjs 的 `transform` 是**乘在 viewport 之上**的

预览缩略图、二维码区域放大、黑白 / 栅格化都要「只把页面的一块区域画进画布」。
做法是给 `page.render()` 传 `transform`，把区域左上角挪到画布原点、顺便放大 s 倍。
这里有个**违反直觉**的行为：

> pdfjs 的 `CanvasGraphics.beginDrawing()` 是**先** `ctx.transform(...params.transform)`、
> **再** `ctx.transform(...viewport.transform)` —— 两者**相乘**。
> 所以 **viewport 必须传 `scale: 1`**，缩放只写在 `transform` 里。

早先两边都写了 `scale`，缩放于是被**平方**（2.66 → 7.05）：画布只有区域那么大，
真正画进去的只有页面左上角 `1/s` 一块（还被放大 `s` 倍）。
症状是**预览里整张票只显示左上角一小块、字特别大、右边和下边像被切断**
（用户报的「发票显示不全」就是它）。特别难查的原因是：白边探测用的是 72 dpi、`scale` 恰好 1，
看起来完全正常；只有放大过的路径（缩略图、黑白 / 栅格化、二维码）才出错。

现在这套参数统一由内核产出：
`regionRenderArgs()`（`packages/core/src/pdf/renderRegion.ts`），
**渲染引擎一处调用**（`lib/render/engine.ts`，缩略图 / 二维码 / 裁白边 / 黑白栅格 / OCR 前栅格
全部经它走 `lib/render/client.ts`，默认在 Worker 里执行）
—— 以前是外壳三处各调一遍，现在只有一处能踩坑。
内核里有一条单测把这个不变量钉住（`packages/core/test/renderRegion.test.ts`），
浏览器里还有像素级回归（`pnpm e2e`：把黑块画在已知位置，里外取点断言黑/白）。
QR 那条路径还有个附带收益：小图（左上角 4×）现在能一次命中，
不必退化到整页扫描（实测 803 ms → 436 ms）。

**自检方法**（不用真的渲染，`getTransform()` 是同步的）：按 pdfjs 的顺序把两个矩阵乘起来，
累计出来的 `a` 必须等于 `scale`，不能是 `scale²`：

```js
const ctx = canvas.getContext("2d");
ctx.transform(...regionRenderArgs(page, s, { x: 0, y: 0 }).transform); // 第一步
ctx.transform(...page.getViewport({ scale: 1 }).transform); // 第二步（pdfjs 里就是这两步）
console.log(ctx.getTransform().a); // 必须是 s
```
