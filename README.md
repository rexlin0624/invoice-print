# 发票工具

本地优先的**发票合并打印 / 查重 / 汇总**工具。把一堆发票拖进来，自动识别、去重、按 A4 排好版，
一张纸放 2 张或 4 张，带裁切线，点一下打印。

**文件不上传。** 解析、排版、打印 PDF 全部在你的浏览器里生成，断网也能用，没有账号系统。

## 快速开始

```bash
pnpm install
pnpm ocr:prepare  # 拉取本地 OCR 资产（worker + wasm 核心 + 中文模型，约 24 MB，已 gitignore）
pnpm dev          # http://localhost:5180

pnpm desktop:dev  # 桌面版：起同一个 Vite(5180) + Tauri 窗口（需要一台内存够的机器，见下）
```

`pnpm ocr:prepare` 是**可选**的：不做的话扫描件/图片识别会提示模型缺失（`ocr-unavailable`），
其余功能不受影响。资产来自 npm 包与 `naptha/tessdata`，**校验 sha256 后**写入
`apps/web/public/ocr/`，运行时不发任何外部请求。

> 注意 `apps/web/public/ocr/` 在 git 里是 ignore 的，但 **Vite 会把 `public/` 原样拷进 `dist/`** ——
> 也就是说 `pnpm build` 出来的产物**是带这 24 MB OCR 资产的**，这是故意的：
> 只有跟着产物一起分发，装到没网的机器上 OCR 才能用。它们只是引擎与语言模型，不含任何发票数据。
> 真票样本走的是另一条路（dev 中间件），**永远不会进 `dist/`**，见下。

其它命令：

```bash
pnpm test         # 内核回归（含 samples/ 真票全字段比对）+ 外壳桥单测
pnpm typecheck    # 全部子包
pnpm build        # 产出 apps/web/dist（不含任何发票样本）
pnpm e2e          # 真实浏览器回归：无头 Chrome 跑 12 项渲染检查（缩略图/二维码/裁白边/黑白）
                  # 用 pdf-lib 现场生成夹具，不依赖 samples/；找不到 Chrome 可设 CHROME=/path

pnpm desktop:check   # cargo check --all-targets -j 2（本机唯一无门槛的 cargo 命令）
pnpm desktop:dev     # 起 Tauri 窗口（debug 模式，必须有 Vite 在 5180）—— ⚠️ 默认禁止，见 §Rust 编译纪律
pnpm desktop:build   # 打安装包（release，前端产物内嵌，不需要 dev server）—— ⚠️ 默认禁止`
pnpm desktop:icons   # 重新生成图标（手写 PNG/ICO + macOS iconutil，不用 tauri icon）
```

> `desktop:dev` / `desktop:build` / `desktop:test:rust` 都经过 `apps/desktop/scripts/rust.mjs` 看门：
> 本机会**直接拒绝**并说明原因（要故意闯祸得先设 `ALLOW_RUST_BUILD=1`），
> 免得手一滑把 8 GB 的机器编到重启。放行之后还有两道内存闸：
> 启动前**自检**（可用内存不到 `RUST_MIN_FREE_MB`，默认 3000 MB，就拒绝并列出该退哪个应用），
> 跑起来后**看门狗**（进程树 RSS 超 `RUST_MAX_MEMORY_MB` 或系统可用内存低于 12% 就 SIGKILL 整棵树）——
> 宁可这次检查失败，也不要机器重启。
> 2026-10-18 放行实测：debug 构建 1 m 11 s / 744 MB，release 打包 4 m 07 s / 1178 MB。

**开发用样本**：把真实发票放进 `samples/private/`（内容已 gitignore，绝不入库），
`pnpm dev` 时会由 `vite.config.ts` 里的 dev 中间件按 `/__samples__/*` 提供，
空状态页就会出现「载入 N 张真实样本发票」的一键入口。

> 真票**刻意不放 `apps/web/public/`**：Vite 会把 `public/` 原样拷进 `dist/`，
> 那样真实发票会跟着产物一起被打包 —— 一旦有人把 `dist/` 传上静态托管就等于公开了发票。
> 现在的做法只在 `pnpm dev` 里生效，生产构建里连代码都不会进去。

## 目录结构

```
packages/core        纯 TS 内核（零 DOM / 零 Node API / 零 Rust）
  model/             Invoice、金额（整数「分」）
  text/              token → 行 → 页 → 文档；锚点扫描
  pdf/               pdfjs 区域渲染参数（缩略图 / 二维码 / 栅格化共用）
  parse/             取数阶梯：xml / ofd / pdfText / ocr / 字段抽取
  validate/          校验规则 + 统一社会信用代码校验位 + 购销方交叉校验
  dedupe/            三层查重
  combine/           凑票（greedy + 分支定界）
  layout/            排版几何（唯一一份，unit pt，y 轴向下）
  export/            CSV / xlsx 共用的表格模型
apps/web             网页版（React + Vite）
  src/lib/           外壳能力：pdfjs / 栅格化 / 二维码 / OCR / 打印 / 保存 / IndexedDB
  src/lib/shell.ts   桌面外壳桥（Tauri IPC，网页版是空操作）
  src/test/          假外壳（给外壳桥的单测用）
  scripts/           prepare-ocr.mjs（OCR 资产本地化，sha256 校验）
  public/ocr/        本地 OCR 资产（gitignore，由 pnpm ocr:prepare 生成）
apps/desktop         Tauri 桌面端（M4）：只有 Rust + 配置 + 图标，界面复用 apps/web/dist
  src-tauri/src/     6 个能力模块：app / dialog / files / print / shell / store
  scripts/           make-icon.mjs（图标生成）
samples/             真票样本 + 期望 JSON（内容不入库）
docs/                架构与解析规则参考
```

## 关键约定

- **一套内核，两个外壳。** 业务逻辑全在 `packages/core`；文件 IO 由外壳注入字节流。
- **金额一律整数「分」**（`number`），禁止用浮点存元。
- **排版只输出一次几何**（`LayoutSpec`，pt，y 轴向下）。CSS 与 PDF 各写一个极薄适配器，
  PDF 只 `flipY` 一次，**绝不重新排版**。
- **取数用锚点文字相对定位**，不用绝对坐标。
  来源按可信度分层：`xml/ofd` > `qr` > `pdf-text` > `ocr`，每个字段带 `source` 与 `confidence`。
- **解析器不抛异常**：返回 `{ 结果, issues[] }`；拿不到的字段是 `undefined`，不用空串或 0 冒充。
- **查重的安全边界**：只对「文件相同 / 发票号码相同」自动跳过；
  「销售方 + 金额 + 日期」相同**只标记**，因为同一天在同一家店买两次同价的东西真的会发生。

⚠️ 正在改解析或打印前，请先读 `docs/解析规则参考.md` §7「已知坑」，
尤其是 **pdfjs 会转移你传给它的 ArrayBuffer** 这一条 ——
它只在浏览器里出现，典型症状是「单元测试全绿、网页里全空」。

## 技术选型（与《重构执行方案》的差异）

| 项       | 方案里写的     | 实际用的                          | 为什么                                                                                             |
| -------- | -------------- | --------------------------------- | -------------------------------------------------------------------------------------------------- |
| 内核语言 | Rust           | **TypeScript**（`packages/core`） | 一套内核直接被网页版复用；本机 8 GB，编 Rust 依赖树有内存风险（实测 `-j 1` 可控，见 §Rust 编译纪律）。Rust 留到 M4 当纯外壳 |
| 样式     | Tailwind       | **原生 CSS + 设计令牌**           | 零配置风险，对设计稿的像素级控制更直接                                                             |
| 状态     | Zustand        | **React context + useReducer**    | 不给 M1 多引一个依赖                                                                               |
| 二维码   | —              | **zxing-wasm**                    | 官方 wasm 自己 fetch 同源 `.wasm` 并以 `wasmBinary` 注入，绕开 CDN                                 |
| OCR      | MNN + PP-OCRv6 | **tesseract.js**                  | 一个 wasm 核心 + 一个语言模型就能跑，纯本地；准确率不如 PP-OCR，所以置信度定 0.6 并强制复核        |
| Excel    | —              | **ExcelJS**（懒加载）             | 浏览器构建单文件，947 KB，只在点「导出」时才下载                                                   |

选型切换的成本都还在可控范围：内核是纯函数，换语言等于照着重写一遍；
样式是集中的 `styles.css`；状态集中在 `state/store.tsx` 一个 reducer 里。

## Rust 编译纪律

本机 **8 GB / Apple Silicon**。这条纪律的依据是**代价不对称**：`cargo build` 的完整 codegen
+ **单进程链接**可能在你没看着的时候把可用内存吃掉 1 GB 以上，一次误判就是**整机重启**
（依据与实测见 `AGENTS.md` §1）。

- ✅ `cargo check -j 2`（只产 metadata）
- ❌ 默认禁止 `cargo build` / `cargo test` / `cargo run` / `tauri build`。
  实测 `-j 1` 之下本机跑得动（debug 1 m 11 s / 744 MB；release 打包 4 m 07 s / 1178 MB），
  但默认仍然禁止：峰值可能出现在你走开之后。要走就明示放行 `ALLOW_RUST_BUILD=1`
- ⚠️ 发布包**默认**在 GitHub Actions 里构建；本机出包是例外，不是常规路径
- ⛔ 同一时间只允许一个 cargo 进程
- 🧮 会链接的命令在**启动之前**先自检内存：不到 `RUST_MIN_FREE_MB`（默认 3000 MB）就拒绝，
  并列出现在最吃内存的应用（**退应用，不是退终端**）。`cargo check` 只提醒、不拦。
- 🐕 跑起来的命令有**内存看门狗**：进程树 RSS 超过 `RUST_MAX_MEMORY_MB`（默认 2500 MB）
  或系统可用内存低于 `RUST_MIN_FREE_RATIO`（默认 12%）就 SIGKILL 整棵树 ——
  **宁可这次检查失败，也不要机器重启**

**前端开发不需要任何 Rust。** 详见 `AGENTS.md` §1。
